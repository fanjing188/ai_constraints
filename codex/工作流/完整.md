# 完整模式工作流

> 适用于多文件、跨影响域、高风险、边界不清，或用户要求严格流程 / 独立 Review / 多子代理并行的任务。

## 1. 占位与上下文

- 读取 `ai_constraints/codex/任务池.md`，创建或认领 `[析]` 任务行。
- 完整任务行至少写清：`任务`、`Owner`、`Scope`、`当前动作`、`验证`、`风险`；模块 / 影响域、允许修改、禁止修改和子代理结论写入 `Scope`、`当前动作` 或 `风险`。
- `Scope` 必须写清允许修改和禁止修改边界。
- 先读目标文件和引用处；需要影响域判断时，读模块文档或 `ai_constraints/codex/架构.md`。

## 2. 影响分析与派发决策

- 量化影响文件数、影响域数量、顶层目录数量、是否改接口 / schema / 配置 / 外部集成 / 核心流程，以及是否能拆出互不重叠写入 Scope。
- 满足高风险条件时，补 `ai_constraints/codex/影响分析.md`。
- 需要派发或复核子代理时，读取 `ai_constraints/codex/子代理.md`。
- 按问题域多派 `Explorer`，按互不重叠写入 Scope 多派 `Worker`；没有并行收益或无法隔离 Scope 时，在任务行风险里写 `未使用：原因`。
- 派出 `Explorer` 后，Main Agent 不重复排查同一问题域；派出 `Worker` 后，Main Agent 不并行修改同一写入 Scope。

## 3. 实现

- 分析完成后，把状态从 `[析]` 改成 `[做]`。
- 只在任务行声明的 Scope 内修改。
- 一次只解决当前任务；如果范围扩大，先更新任务行 Scope 和风险。
- 如有子代理参与，Main Agent 必须复核其 diff，确认没有越权、覆盖他人改动或偏离目标。

## 4. 验证与文档同步

- 执行 `bash ai_constraints/scripts/verify.sh [file ...]`。
- 按任务行补跑必要测试或手工验证。
- 高风险、多文件、跨域、改公开接口或用户要求独立复核时，平台允许则派 `Verifier`。
- 涉及模块功能、接口、依赖、配置、外部集成、踩坑或可复用模式变化时，记录是否派 `DocSync`；文档 Scope 可隔离时可并行派发。
- 测试失败回到 `[做]` 修复；无法推进时标 `[阻]` 并写明原因。

## 5. 自查与关单

- 对照 `ai_constraints/codex/自查清单.md` 做 diff 自查。
- 在任务行记录验证证据、子代理结论摘要和残余风险。
- 完成开发、验证和必要文档同步后，移动到“待验收”，状态改为 `[待验]`。
- `验收方` 为 `用户` 时等待用户验收；`验收方` 为 `AI` 时由 Main Agent 验收，通过后删除或归档。
