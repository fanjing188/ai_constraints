# 轻量模式工作流

> 适用于同一影响域内 1-3 个文件，风险和验证方式明确，但需要任务池锁定 Scope 的改动。

## 1. 任务池锁定

- 读取 `ai_constraints/codex/任务池.md`。
- 在“正在执行”创建或认领任务行，状态设为 `[析]`。
- 最少写清：`任务`、`Owner`、`Scope`、`验证`、`风险`。
- 如果发现和其他 `[析]`、`[做]`、`[阻]`、`[待验]` 任务 Scope 重叠，先标 `[阻]` 并写明冲突点。

## 2. 上下文加载

- 只读目标文件、必要调用方和必要测试。
- 有明确影响域但文件路径不足以判断边界时，再读对应模块文档。
- 默认不读 `子代理.md`、`影响分析.md`、`架构.md`、`坑点.md`、`模式.md`。

## 3. 实现与升级

- Main Agent 直接实现，不派子代理。
- 只改任务行声明的 Scope，不顺手修别的问题。
- 发现任一情况时，先升级到完整模式并补齐任务行：超过 3 个文件、跨影响域、跨顶层目录、改公开接口 / schema / 配置 / 外部集成 / 核心流程、BUG 路径不清或用户要求独立 Review。

## 4. 验证与验收

- 执行 `bash ai_constraints/scripts/verify.sh [file ...]`。
- 按任务行补跑必要测试或手工验证。
- 检查 diff 是否符合 Scope。
- 记录验证证据和风险；完成后移动到“待验收”，验收方按任务行约定填写。
