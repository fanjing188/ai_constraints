## 使用规则

- 状态：`[待]` · `[析]` · `[做]` · `[阻]` · `[待验]`
- `[待]` 放在“候选任务”；`[析]`、`[做]`、`[阻]` 放在“正在执行”；完成开发和自测后移到“待验收”。
- 验收通过后从任务池删除；需要留痕时，把摘要写入“里程碑归档”或 `归档/{milestone}.md`。
- `验收方` 为 `用户` 时，由用户验收后删除；`验收方` 为 `AI` 时，Main Agent 按验收方式执行确认，通过后自行删除或归档。
- 处于 `[析]`、`[做]`、`[阻]`、`[待验]` 的任务默认只允许 `Owner` 修改。
- `Scope` 明显重叠的两个任务，不要同时进入执行态；先标成 `[阻]` 并写明冲突点。
- 子代理不得修改任务状态；`子代理`、`验证证据` 和 `风险备注` 由 Main Agent 维护。
- 派发子代理只记录摘要，详细交接按 `ai_constraints/codex/子代理.md`。

## 表格字段

| 字段 | 说明 |
|------|------|
| ID | 任务编号，例如 `T01` |
| 状态 | `[待]` / `[析]` / `[做]` / `[阻]` / `[待验]` |
| 任务 | 一句话说明需求 |
| 模块 | 业务模块名 |
| Owner | 当前主控窗口或负责人 |
| Scope | 允许改动的目录、文件或入口 |
| 当前动作 | 正在分析、实现、阻塞原因或待验收事项 |
| 验证 / 验收 | 执行态写验证方式；待验收态写验收方式 |
| 子代理 | 角色和结果摘要；未使用写 `未使用` |
| 风险备注 | 阻塞、残余风险、需要人工确认的点 |
