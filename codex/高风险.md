# 高风险改动

> 仅在入口触发条件命中时读取。本文件只增加高风险检查，不重复默认执行路径。

## 先确认影响

- 列出受影响的模块档案、公开调用方、数据读写方和外部消费者。
- 区分内部实现调整、兼容契约变化和破坏性变化；新增公开能力不自动等于破坏性变化。
- 明确数据迁移、配置发布顺序、权限边界、失败行为和回滚方式。
- 认证、支付、金额、权限和核心状态机变化必须检查绕过路径、重复提交和并发冲突。

## 实现约束

- 先修改主路径，再处理已经确认的边界，不添加无明确需求的兼容层或静默兜底。
- 破坏性变化必须同步所有已确认调用方；不能只修改被调用处。
- schema 或持久化格式变化必须说明旧数据处理方式，不以运行时猜测代替迁移。
- 外部依赖失败必须选择明确行为：报错、重试或降级；只有需求明确允许时才能降级。
- Scope 扩大到新模块时，先读取对应档案并重新确认验证范围。

## 验证要求

- 覆盖主路径、关键不变量、失败路径、权限边界和数据兼容性。
- 除模块快速验证外，补跑受影响调用方或更高一层集成验证。
- 数据或配置变化应验证升级和回滚路径；无法自动验证时给出可执行的手工步骤。
- 完成后独立检查实际 diff、调用方同步、档案同步和残余风险。

## 交付清单

- [ ] 影响模块和调用方已经确认
- [ ] 契约、数据、权限和失败语义明确
- [ ] 没有未经需求确认的兼容或兜底逻辑
- [ ] 关键不变量有验证证据
- [ ] 必要的模块档案和模块地图已同步
- [ ] 回滚方式和残余风险已说明
