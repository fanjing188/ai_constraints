# 自查清单

> 改完代码后，从 diff 和验证证据两个角度过一遍。
> 目标不是证明“我写完了”，而是尽快找出还没补齐的地方。

## 1. 声明对齐

- `当前任务.md` 里的“改什么”与实际 diff 是否一致
- `当前任务.md` 里的“不加什么”是否真的没有夹带
- 范围如果扩大了，是否已经先更新 `当前任务.md` 或回退多余改动

## 2. 影响面

- 改公开接口、数据结构、配置时，是否列出了所有调用方和受影响模块
- 兼容改动还是破坏性改动，是否说清楚了
- 高风险改动是否补了 `影响分析.md`

## 3. 验证证据

- 跑了哪些命令
- 自动化结果如何：通过 / 失败 / 跳过
- 没有自动化时，手工验证了哪些路径
- 关键边界是否真的验证过：空值、越界、查不到、外部失败、并发冲突

## 4. 可读性

- 新增或修改的代码逻辑是否带中文注释
- 复杂逻辑的注释是否解释了“为什么”
- 命名是否能直接看出职责，不需要读实现才理解

## 5. 文档同步

- 接口 / 依赖变化是否同步到 `架构.md` 和相关 `模块/{name}.md`
- 新坑是否补到 `坑点.md`
- 新模式是否补到 `模式.md`
- 任务状态和技术决策是否同步到 `任务池.md`

## 6. 风险结论

- 当前改动最大的回归风险是什么
- 哪些点还需要人工验收
- 如果这次先不做的内容以后再做，最容易踩的坑是什么
