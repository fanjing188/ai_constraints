# Codex 项目入口

> 默认围绕当前功能模块工作。规则按触发条件增量读取，不预读整套文档。

## 默认路径

1. 从用户给出的路径、符号、报错或 `rg` 结果定位目标模块。
2. 修改前读取目标代码目录向上最近、且不是项目根的 `AGENTS.md`。没有就近档案时，用模块名、代码路径或关键符号在 `codex/模块/` 定位集中档案；无法唯一匹配时才读 `codex/架构.md` 的模块索引。不要加载无关模块。
3. 再读取主入口、直接调用方和相关测试，确认档案仍与代码一致；代码和测试是当前实现的事实来源。
4. 明确本次 Scope、受影响的不变量和验证方式，只做解决当前需求的最小修改。
5. 执行模块档案声明的验证命令；档案未声明时，使用项目已有的精确测试、类型检查或构建命令，不猜测测试框架。
6. 检查实际 diff、验证结果和残余风险后交付。

只读任务执行“定位 -> 读取 -> 回答”，不进入修改、任务锁或文档同步流程。

## 增量规则

| 触发条件 | 额外读取 |
|---|---|
| 跨模块修改，或需要判断系统级依赖 | `codex/架构.md` 和受影响模块档案 |
| 破坏性契约、schema、认证、支付、权限、配置、部署、外部集成或核心状态机变化 | `codex/高风险.md` |
| 存在多个活跃 Owner、多窗口并行、跨会话交接或共享热点文件冲突 | `codex/任务池.md` |
| 真实并行、派发或复核子代理 | `codex/协作.md`；存在写入冲突风险时再读取 `codex/任务池.md` |

文件数量不是风险等级。多个同构文件可以低风险，单个认证、金额或状态机文件也可能高风险。

## 模块档案同步

只有稳定事实发生变化时更新模块档案：用户可见能力、模块边界、主流程、业务不变量、公开契约、状态或数据结构、依赖、入口路径、风险点、验证方式。

- 新模块完成后创建档案；已有模块尚无档案，且本次新增或改变了稳定功能板块时，也在同一任务补建。按 `codex/模块/_模板.md` 在模块目录创建 `AGENTS.md`；模块跨多个目录时，改为在 `codex/模块/{模块名}.md` 维护唯一档案，并登记到 `codex/架构.md`。
- 更新现有章节，不追加任务日志、聊天过程、临时方案、逐函数说明或可直接从代码读取的细节。
- 纯内部重构、变量改名和不改变稳定行为的修复，不更新模块档案。
- 模块特有坑点写入模块档案；跨模块通用约束和风险写入 `codex/架构.md`。

## 不可跳过的边界

- 不覆盖用户或其他 Owner 的未提交改动；发现 Scope 冲突先停止对应写入。
- 不提交密钥、Token 或凭证，不执行未经允许的破坏性操作。
- 公开契约、数据和核心流程变化必须检查调用方、迁移影响和回滚路径。
- 实现完成必须提供验证证据；无法自动验证时明确说明手工路径和残余风险。
