# Codex 项目入口

> 默认走 R0/R1；代码与测试是事实源。修改任务收尾默认执行 `$project-update`。

## 五步闭环

1. **算半径**：从目标或实际 diff 确认模块、契约、共享状态、配置和直接消费者。
2. **定等级**：按语义与影响半径定 R0–R3，不按文件数量。
3. **跑闭包**：执行最小验证集合；完整门禁只在最终交付或升级时运行。
4. **核对 diff**：确认修改未越界；越界就重新分级、补读取与验证。
5. **同步档案**：稳定事实变化才更新 generated 区块，否则保持零 diff。

只读任务执行“定位 → 读取 → 回答”，不进入修改、档案同步或任务锁。

## 风险与最小闭包

| 等级 | 触发条件 | 最小读取与验证 |
|---|---|---|
| R0 | 文档、注释、格式且产物不变 | 目标文件；`git diff --check`，规则包变更再跑规则验证 |
| R1 | 私有实现或局部修复，公开行为与副作用不变 | 目标代码、最近模块档案、精确测试 |
| R2 | 公开接口、schema、事件、共享类型/配置或持久化格式变化 | A 档案、直接消费者、相关测试与必要架构地图 |
| R3 | 认证、支付、金额、权限、状态机、迁移、部署、外部集成或未知半径 | R2 全部 + `ai_constraints/codex/高风险.md`，覆盖失败、并发和回滚 |

以下情况升级：缺少真实档案；消费者与引用不一致；命令不可执行；共享契约变化；生产代码与既有断言同改；局部检索后仍无法证明影响半径；实际 diff 越界。

R0/R1 不默认读取架构地图、全部调用方、高风险、协作或任务池。契约变化、跨模块或高风险时再展开；真实派发前读 `ai_constraints/codex/协作.md`，仅有写入冲突风险时读 `ai_constraints/codex/任务池.md`。

## 模块档案同步

`$project-update` 是修改任务的默认收尾步骤，不需用户再次提醒。只同步用户能力、模块边界、不变量、契约、状态/数据、依赖、风险或验证等稳定事实；纯内部重构不更新。新模块按模板建立唯一档案并登记地图，不写任务日志、聊天或逐函数说明。

## 不可跳过的边界

- 不覆盖用户或其他 Owner 的未提交改动；冲突时停止对应写入。
- 不提交秘密，不修改任务外业务代码，不执行未经授权的破坏性操作。
- 契约、数据与核心流程变化必须核对消费者、迁移影响和回滚路径。
- 收尾检查实际 diff、验证和残余风险；无法自动验证时报告原始阻塞与手工路径。
