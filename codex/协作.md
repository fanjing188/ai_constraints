# 并行与子代理协作

> 只有真实并行、派发或复核子代理时读取。主代理始终负责最终整合、验证和交付。

## 启用条件

- 存在可以并行推进的独立问题域，或可以隔离的非重叠写入 Scope。
- 用户要求独立复核，或高风险任务需要独立验证。
- 并行收益必须大于交接、等待和复核成本；普通局部修改由主代理直接完成。

## 角色

| 角色 | 权限 | 输出 |
|---|---|---|
| Explorer | 只读 | 事实、调用路径、风险和建议 Scope |
| Worker | 仅指定写入 Scope | 修改、验证结果和残余风险 |
| Verifier | 只读 | 测试结果、diff 风险和遗漏验证 |
| DocSync | 仅指定档案 | 与代码事实一致的档案修改 |

## 交接包

派发时写清：目标和完成标准、允许读取范围、允许修改的精确 Scope、禁止事项、验证要求和返回格式。只读角色的写入 Scope 必须为 `无`。

存在并发写入时，由主代理先在 `codex/任务池.md` 登记 Scope；子代理不得自行修改锁。

## 并发边界

- Explorer 返回前，主代理不重复排查同一问题域。
- Worker 执行时，主代理和其他 Worker 不修改相同写入 Scope。
- 多个子代理应先连续派发，再统一等待；没有独立工作时不制造并行任务。
- 子代理发现冲突、越权需求或信息不足时停止写入并返回，不自行扩大范围或添加兜底。

## 主代理复核

- 检查子代理是否越权、覆盖现有未提交改动或偏离目标。
- 复核 Worker 和 DocSync 的 diff，不能只接受文字摘要。
- 判断 Verifier 的命令是否覆盖模块档案中的不变量和本次风险。
- 汇总所有结果后，由主代理执行必要的最终验证并对外给出结论。
