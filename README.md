# ai_constraints vNext — Codex 多窗口与多子代理任务并行范式

面向 Codex 多窗口并行执行不同任务、单任务内部由 Main Agent 派发短生命周期子代理的协作模板。核心目标不是“让多个代理自由协商”，而是让 Main Agent 在自己的任务闭环里推进：先接需求、占位认领、分析补全任务行、按需派发子代理、执行、自测、文档同步、移动到待验收、验收后删除或归档，并围绕对应业务模块文档加载精准上下文。

## 快速开始

把模板放进项目根的 `ai_constraints/` 目录后，执行：

```bash
bash ai_constraints/setup.sh
```

安装完成后优先填写这四个文件：
- `ai_constraints/codex/入口.md`：项目快照、会话加载顺序、硬规则
- `ai_constraints/codex/任务池.md`：当前里程碑、表格看板、范围边界、验证与验收方式
- `ai_constraints/codex/架构.md`：业务模块地图、依赖关系、全局约定
- `ai_constraints/codex/子代理.md`：按需调整 Main Agent 派发子代理的角色、权限和交接格式

## 设计原则

- 任务看板优先：每个窗口先从 `ai_constraints/codex/任务池.md` 找到自己的任务行，再开始读代码
- 需求先占位：当前窗口收到新需求时，先在 `任务池.md` 的“正在执行”建任务行并认领，再分析和实现，避免其他窗口误碰
- 主控代理负责制：Main Agent 决定是否派发子代理，并负责复核、合并、验证结论和任务状态回写
- 子代理短生命周期：Explorer / Worker / Verifier / DocSync 只处理明确分派的局部任务，不拥有完整任务
- 业务模块优先：模块文档按系统业务能力写，一份模块一份文档，不按代码目录拆
- 按需加载上下文：先读任务行和对应模块文档，再去加载相关实现、调用方和约束文档
- Plan Mode 优先：实现前先探索代码和文档，能从仓库确认的事实不要先问用户
- 最小 diff：只改本次任务声明的内容，不顺手修、不夹带抽象、不悄悄扩范围
- 验证闭环：实现完成后完成验证与必要文档同步，再做自查和任务状态回写
- 中文协作：新增或修改的代码逻辑带中文注释，提交说明用中文

## 日常工作流

1. 当前窗口收到新需求时，先在 `ai_constraints/codex/任务池.md` 的“正在执行”新建并认领任务行，状态标成 `[析]`
2. 分析需求后，补全任务行里的 `模块`、`Scope`、`当前动作`、`验证`、`风险备注`
3. 再读对应的 `ai_constraints/codex/模块/{业务模块}.md`，按业务模块加载上下文
4. 任务复杂时按 `ai_constraints/codex/子代理.md` 派发 Explorer / Worker，并在任务行记录 `子代理`
5. 实现完成后默认派 Verifier；涉及接口、模块规则、依赖或流程变化时并行派 DocSync
6. Main Agent 复核子代理输出，对照 `codex/自查清单.md` 做 diff 自查，完成后移动到“待验收”
7. 用户验收通过后删除任务行；如果 `验收方` 是 `AI`，Main Agent 验收通过后自行删除或归档

## 适用场景

| 场景 | 说明 |
|------|------|
| 小到中型项目 | 默认目标，尤其适合 5 到 20 个模块的服务或应用 |
| 多个 Codex 窗口并行 | 不同窗口各自执行不同任务，边界以任务行和业务模块划分 |
| 单任务多子代理协作 | 主控代理拆分探索、实现、验证和文档同步，最后统一合并 |
| 有测试基础的项目 | `scripts/verify.sh` 会优先帮助你跑到相关测试 |

## 不适用场景

- 多个窗口频繁同时改同一文件：需要更强的分支策略或人工协调，单靠任务看板不够
- 子代理需要长期自治的团队流程：本模板只支持 Main Agent 派发短任务，不支持代理长期自组织
- 多团队长期并行协作：需要更强的流程和仓库治理，不建议只靠这套模板
- 完全没有测试的项目：模板仍可用，但验证环节需要手工补足，收益会打折

## v5 -> vNext 迁移

本版把“单任务单例状态”收束成“多窗口共享任务池 + 业务模块文档”，主要变化如下：

- `当前任务.md` 从主流程移除，任务范围、边界、验证与验收方式统一写进 `codex/任务池.md`
- `任务池.md` 承担完整任务生命周期：`[待] -> [析] -> [做] -> [待验] -> 删除 / 归档`
- `子代理.md` 新增 Main Agent 派发协议，规定 Explorer / Worker / Verifier / DocSync 的权限与交接格式
- `模块/*.md` 从“代码目录说明”改成“业务模块说明”
- `架构.md` 只保留系统级模块地图和依赖，不再展开模块细节
- 默认工作流改为：需求进入窗口 -> 任务池占位认领 -> 分析补全任务行 -> 模块文档 -> 按需派发子代理 -> 代码实现 -> 验证与文档同步 -> 待验收 -> 删除 / 归档

迁移时不保留旧的单任务执行契约。把项目根 `AGENTS.md` 改成引用 `@ai_constraints/codex/入口.md` 后，按新模板结构补齐内容即可。
