# 更新升级规则

## 风险分级

- R0：非行为文档、注释或格式变化，仅运行空白与相关规则验证。
- R1：模块内私有实现变化，运行模块精确测试和对应不变量测试。
- R2：公开接口、schema、事件、共享类型/配置、缓存键或持久化格式变化；展开每个直接消费者并运行 A 模块与 B/C 契约或冒烟验证。
- R3：认证、支付、金额、权限、核心状态机、迁移、部署、外部集成或未知半径；在 R2 上增加集成/E2E、失败、并发、升级回滚与独立验证。

## 强制全量重扫

任一条件命中即切换到初始化扫描阶段，但保留全部 manual 区块：

- 状态缺失、损坏或 schema 不兼容。
- `indexed_commit` 不存在、不是 HEAD 祖先或历史被重写。
- 新增、删除、拆分、合并模块或顶层第一方源码目录。
- 包管理器、主要框架、构建、测试、CI 或部署入口变化。
- schema、共享注册表、路由生成器、状态中心或核心配置结构变化。
- 变化文件无法唯一映射到模块。
- 状态消费者与代码引用不一致，或消费者为 `UNKNOWN`。
- 影响半径无法证明。

所有升级条件都按正常 `$project-update` 自动进入全量扫描；新状态只有在档案标记、manual 字节和实际验证全部通过后才落盘。

## 强制风险升级

缺少真实模块档案、验证命令占位或不可执行、共享契约变化、生产代码与既有测试断言同改、无法证明公开契约不变、实际 diff 越界时，不能保留 R1。消费者为空但代码存在外部引用时按 R3，并保留不一致证据。
