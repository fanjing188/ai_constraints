# 更新升级规则

## 风险分级

- R0：非行为文档、注释或格式变化，仅运行空白与相关规则验证。
- R1：模块内私有实现变化，运行模块精确测试和对应不变量测试。
- R2：公开接口、schema、事件、共享类型/配置、缓存键或持久化格式发生语义变化；展开直接消费者并运行生产者与消费者契约或冒烟验证。
- R3：认证、支付、金额、权限、核心状态机、迁移、部署、外部集成，或局部核对后仍无法确定影响半径；在 R2 上增加集成/E2E、失败、并发、升级回滚与独立验证。

## 优先局部核对

- 变化文件无法映射模块：读取该文件、最近入口、引用和测试，能确认归属就增量更新；只有真实新模块或边界变化才全量重扫。
- 直接消费者为 `UNKNOWN`：搜索导入、调用、路由、注册和测试引用；找到后补充消费者，仍未知再按 R3。
- schema、registry、共享配置等路径变化：先判断公开语义是否变化。纯内部调整走 R1，真实契约变化走 R2，不按文件名直接 R3。
- 秘密、二进制或其他排除文件仅元数据变化：不读取内容，只判断路径是否属于运行配置；按实际影响处理，不因此全量扫描代码。
- 生产代码与测试断言同改：核对测试是否只是适配新需求，不能据此单独判定实现错误或强制全量重扫。

## 强制全量重扫

- 状态缺失、损坏、schema 不兼容，或 `indexed_commit` 不存在、不是 HEAD 祖先、历史被重写。
- 已确认新增、删除、拆分、合并模块，或顶层第一方源码布局发生结构性变化。
- 包管理器、主要框架、构建、测试、CI 或部署入口变化并改变项目命令、产物或架构。
- 现有模块根重叠、档案映射冲突或消费者证据矛盾，局部修复无法恢复唯一关系。
- 完成局部读取、引用检索和必要测试后仍无法证明影响半径。

全量重扫保留全部 manual 区块；新状态只有在档案标记、manual 字节和实际验证全部通过后才落盘。

## 强制风险升级

缺少真实模块档案、验证命令占位或不可执行、共享契约或持久化格式变化、关键安全流程变化、实际 diff 越界时不能保留 R1。消费者与代码引用不一致时先补检索证据；无法消除不一致再按 R3。
