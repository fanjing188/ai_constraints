# 增量更新合同

## 输入与基线

读取项目状态、当前 HEAD、工作树、未跟踪第一方文本、`indexed_commit..HEAD` 变化、现有架构与模块档案。状态中的文件指纹覆盖未提交变化；Git 基线用于确认历史仍可增量追踪。

## 增量优先

1. 排除 `ai_constraints/` 后计算业务变化。
2. 将变化文件映射到状态中的模块根。唯一映射直接进入增量；零匹配先读取文件、最近模块、引用和测试判断归属；多匹配先核对重叠根，不能安全判定时再全量重扫。
3. 公开契约、共享数据或状态声明发生语义变化时，展开已确认消费者；消费者为 `UNKNOWN` 时先搜索真实引用，不因占位值直接全量重扫。
4. 只读取变化模块、消费者、相关测试和必要任务/构建配置。
5. 根据代码与测试更新 generated 区块，并保持 manual 字节不变。
6. 执行风险等级的最小验证闭包；失败时不更新状态基线。
7. 验证成功后用最终扫描刷新 `indexed_commit`、项目指纹、文件清单与最近验证状态。

机械分析结果是保守信号，不是最终语义结论。文件名包含 schema、registry、auth 或配置词，只决定优先核对内容和引用；是否升级由实际契约、模块边界和验证影响决定。

## 无变化

`changed` 与 `check` 均返回 `no-change` 后，输出“项目档案已是最新”。不要重写状态或 Markdown，不刷新时间，不运行完整业务测试。以更新前后文件哈希或 Git diff 证明零写入。

## 全量回退

以下情况直接全量重扫：状态或历史基线无效；已确认的模块新增、删除、拆分或合并；主要框架、包管理、构建、测试、CI 或部署入口发生结构性变化。其他不确定项先局部读取与引用检索，只有仍无法证明影响半径时才全量重扫。

## 删除与重命名

- 只用路径历史、公开契约和消费者证据确认重命名，不能只依赖名称相似度。
- 删除档案前确认模块代码、公开契约和消费者均已不存在。
- 待删档案 manual 区块含人工内容时不自动删除；保持文件并报告待处理项。
- 不把待处理项、任务日志或验证记录追加到长期 Markdown。

## 人工区保护

更新前记录每个 manual 区块的原始字节。标记缺失、重复、嵌套或顺序异常时停止；不要先修改再回滚。更新后逐文件比对，任何差异都使更新失败且状态不得前移。
