# 全仓扫描合同

## 完成定义

对项目中每个相关第一方文件给出且只给出一种结果：已列入 `eligible_files` 并由 Codex 实际读取，或列入带原因的排除摘要。脚本负责枚举、读取以计算指纹和排除秘密；Codex 仍需读取合格文本以理解语义。

## 必须读取

- 根治理文件、现有 `AGENTS.md`、README、产品、架构与开发文档。
- 包管理、构建、类型检查、lint、测试、CI、容器与部署配置。
- 第一方源码、入口、路由、API、schema、迁移、共享类型、注册表、配置加载、状态管理与测试。
- Git 已跟踪文件和扫描范围内相关的未跟踪第一方文本。

## 必须排除

- `.git/` 和 `ai_constraints/` 工作包自身。
- `node_modules/`、`.next/`、`dist/`、`build/`、`coverage/`、`vendor/`、`.venv/`、缓存与生成目录。
- 图片、字体、音视频、压缩包、数据库、编译产物、二进制和超大 minified 文件。
- `.env*`、证书、私钥、凭证、Token 与常见秘密路径。只记录路径存在和 `secret` 原因，绝不读取内容。

## 读取与分析顺序

1. 核对 Git 根、HEAD、工作树与未跟踪文件；不要清理或覆盖用户改动。
2. 保存清单与排除原因，确认稳定排序和计数一致。
3. 读取治理、说明、任务、CI、构建与测试配置，提取真实命令候选。
4. 读取代码与测试，按职责和依赖证据建立稳定模块边界，不按文件数量拆分。
5. 对主要能力追踪入口、调用、领域逻辑、状态/数据、副作用和验证。
6. 对公开契约、共享状态、schema、事件和注册表反查直接消费者；无法证实写 `UNKNOWN`。
7. 从已有测试和代码提取不变量；只有描述没有实现入口与验证证据时不得标记为已确认。

大型仓库可让只读 Explorer 分区读取，但分区不得重叠，主代理必须持有完整清单并汇总所有结果。
